> 归档：旧版全量交付计划。当前范围见 `06_当前版本策划案_v1.md`。

7. 14 天排期与验收清单
8. DOCX / PDF 交付版

## 三、每日工作量建议

| 类型 | 每日投入 | 说明 |
|---|---|---|
| 剧本写作 | 3–4 小时 | 每天 2–3 场，约 1500–2500 字 |
| 文本表 | 2–3 小时 | 按 ID 填，不追求文采，先求可用 |
| 评审/修改 | 1–2 小时 | 当天写、次日改 |
| 排版/导出 | 最后 2 天 | 预留缓冲 |

如果只有一个人，D3–D5 的剧本量会偏大，建议提前在 D2 把章节表锁死，写作时不再改结构。

## 四、评审节点

### G1 · 概念确认（D1）

确认：

- 游戏名、类型、平台、时长
- 风格基准：向《Servant of the Lake》靠拢
- 内容边界：不拿 Vanderboom、动物头、炼金术
- 首版范围：七夜、七谜题、三结局

### G2 · 故事确认（D5）

确认：

- 七夜是否每夜都有“值班表 + 秘密 + 潮针 + 旅馆变化”
- Lan/Mother/Chao 的动机是否成立
- 三个结局是否都能从前面七夜自然长出来

### G3 · 剧本/文本评审（D8）

确认：

- 角色声音是否可区分
- 是否还有解释设定的对白
- 每夜是否有 2–3 个日常小互动
- 文本是否适合 4:3 舞台 + 短气泡

### G4 · 文本锁定（D10）

确认：

- 术语统一
- 文本 ID 与场景/物件/UI 对应
- flags 与结局条件一致
- 字数在目标范围内

### G5 · 终审（D13）

只改阻断性问题：

- 错字/病句
- 术语不一致
- 结局条件矛盾
- 文件打不开/目录错

## 六、验收标准

- [ ] 七夜剧本完整，能顺读，不靠设定集补充。

- [ ] 每个角色有独立声音；换台词会出戏。
- [ ] 全量文本可逐条对应到场景/物件/UI。
- [ ] 术语统一，文本 ID 无重复。
- [ ] 风格规范能指导一张 101 概念图。
- [ ] DOCX/PDF 目录、页码、字体正常。
- [ ] 两周内完成，不靠熬夜补稿。

## 七、风险与应对

| 风险 | 迹象 | 应对 |
|---|---|---|
| 范围失控 | 想加第八夜、加多主角、加开放世界 | 回到 7 夜/7 谜题/3 结局；新增内容进“后续” |
| 剧本过长 | 单夜超过 2500 字，对白解释多 | 砍旁白、砍复述、让物件说 |
| 风格跑偏 | 文本像小说，不像游戏 | 每场先写“玩家在做什么”，再写台词 |
| 谜题与文本脱节 | 谜题解法无法用文本提示 | 每条谜题链先写“玩家看到什么/为什么这么做” |
| 美术无法落地 | 写了 20 个场景，预算只够 10 个 | 复用大厅/走廊；每夜只换客房与 1 个公共区域变化 |
| 本地化困难 | 大量谐音/字形梗 | 只保留可解释的双关；文本 ID 化 |
| 交付前崩 | 最后一天还在改剧情 | D10 文本锁定；D13 只改阻断性问题 |

## 八、需要你确认的 6 件事

1. **团队规模**：2–5 人，还是单人？决定是否保留全部 7 夜。
2. **平台**：PC 优先，还是 PC + 移动同步？
3. **语言**：只做中文，还是中英同步？
4. **配音**：关键台词配音，还是全文本为主？
5. **美术管线**：手绘外包，还是程序化/半手绘？
6. **交付对象**：给投资人/老师/团队/外包？决定 DOCX/PDF 的包装程度。

不确认也能推进，但以上会直接影响文本长度、场景数和交付格式。
